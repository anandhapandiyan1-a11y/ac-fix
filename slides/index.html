API Endpoints 📡

Full-stack communication layer (FastAPI — interactive docs at /docs).

POST   /api/auth/register      Create customer or mechanic
POST   /api/auth/login         Issue JWT token
GET     /api/auth/me            Current user profile
GET     /api/services           Service catalog + prices
GET     /api/mechanics?lat,lng  Nearby mechanics (distance)
GET     /api/mechanics/{id}     Mechanic detail + reviews
POST    /api/bookings           Create booking
GET     /api/bookings/my        My bookings (role-based)
PATCH   /api/bookings/{id}/status  Status transitions
GET     /api/bookings/stats     Dashboard stats
POST    /api/reviews?booking_id Rating + comment

Slide 9/12

Data Model 🗄️

Secure SQLAlchemy schema — relationships shown below.

User

id, name, email, phone, role, password_hash

role ∈ {customer, mechanic}

MechanicProfile

user_id, skills, experience, base_fee, verified, lat, lng

Service

name, description, base_price, estimated_time, icon

Booking

customer_id, mechanic_id, service_id, status, total_price, lat, lng

status ∈ {PENDING, ACCEPTED, ON_THE_WAY, COMPLETED, CANCELLED}

Review

booking_id, customer_id, mechanic_id, rating, comment

rating ∈ {1..5} ⭐


Relationship Map
═══════════════════════════════════════════════

User 1 ────┐
  │        │ 1:1
  └ MechanicProfile        ⭐ avg(rating)
  │        ┌ 1:N ──┐
  │        │       │
  └ Bookings(booking.mechanic_id)
              │
              ├ Booking 1 ─── 1 Review
              │   (status flow)
              │
              └─ Service (catalog)

User (customer) 1 ── N Bookings (booking.customer_id)
Booking ── 1 Review (rating + comment)
Review feeds back into MechanicProfile.rating

Status state-machine (enforced in PATCH):
PENDING → ACCEPTED | CANCELLED
ACCEPTED → ON_THE_WAY | CANCELLED
ON_THE_WAY → COMPLETED
